# Q2. Answer any TWO out of FOUR [10]

## Q2.1 Short notes on linear and non-linear data structures (two examples each).

- **Linear:** elements are arranged in a sequence; each element has at most one predecessor and one successor; traversed in a single run. Examples: **array, stack, queue, linked list**.
- **Non-linear:** elements are arranged hierarchically or as a network; one element can connect to many; cannot be traversed in a single run. Examples: **tree, graph** (also heap).

| Linear | Non-linear |
|---|---|
| Single level | Multiple levels |
| Easy to implement | More complex |
| Memory may be wasted (arrays) | Memory used as needed |
| Array, stack, queue, linked list | Tree, graph |

## Q2.2 Explain Big O, Big Omega and Big Theta with examples and graphs.

- **Big O (upper bound):** f(n) = O(g(n)) if there exist c > 0 and n₀ such that **0 ≤ f(n) ≤ c·g(n)** for all n ≥ n₀. Used for the **worst case**. Example: 3n + 2 = O(n) with c = 4, n₀ = 2.
- **Big Omega (lower bound):** f(n) = Ω(g(n)) if **0 ≤ c·g(n) ≤ f(n)** for all n ≥ n₀. Used for the **best case**. Example: 3n + 2 = Ω(n) with c = 3, n₀ = 1.
- **Big Theta (tight bound):** f(n) = Θ(g(n)) if **c₁·g(n) ≤ f(n) ≤ c₂·g(n)** for all n ≥ n₀. Example: 3n + 2 = Θ(n) with c₁ = 3, c₂ = 4, n₀ = 2.

**Graphs:** for O, draw f(n) staying *below* c·g(n) after n₀; for Ω, f(n) stays *above* c·g(n); for Θ, f(n) is sandwiched between c₁·g(n) and c₂·g(n). Mark n₀ on the x-axis in each graph. See *DSA Study Guide › Unit 1*.

## Q2.3 What is an Abstract Data Type (ADT)? How is it different from a data structure?

An **ADT** is a mathematical model of a data type defined only by its **values and operations**, without saying how they are implemented. Example: **Stack ADT**: push, pop, peek, isEmpty, with LIFO behaviour.

A **data structure** is a concrete **implementation** that stores data in memory: e.g. a stack implemented using an array or a linked list.

| ADT | Data structure |
|---|---|
| Logical view: *what* | Physical view: *how* |
| Implementation-independent | Implementation-specific |
| Stack, Queue, List ADT | Array, linked list |

## Q2.4 Time complexity of:

**a) `for (i = 0; i < n; i = i*2) { statement(s); }`**
As written, `i` starts at **0**, and 0 × 2 = 0, so the loop **never terminates** (infinite loop). If `i` started at 1, `i` takes values 1, 2, 4, … < n, i.e. about log₂ n iterations → **O(log n)**. Mention both in the exam.

**b) `for (i = 0; i < n; i += 100) { statement(s); }`**
Runs n/100 times → **O(n)** (constants are dropped).

**c) Is f(n) = n² log n greater than f(n) = n (log n)¹⁰?**
Divide both by n log n: compare **n** with **(log n)⁹**. Any positive power of n grows faster than any power of log n, so **yes, n² log n grows faster** (n (log n)¹⁰ = O(n² log n)).

# Q3. Answer any TWO out of FOUR [10]

## Q3.1 What is recursion? Pseudocode for factorial using recursion.

**Recursion** is when a function solves a problem by calling **itself** on a smaller input, until it reaches a **base case** that is answered directly.

```
Function FACT(n)
1. [Base case]       If n = 0 or n = 1 then Return 1
2. [Recursive step]  Return n × FACT(n − 1)
```
Trace: FACT(4) = 4 × FACT(3) = 4 × 3 × FACT(2) = 4 × 3 × 2 × FACT(1) = 24. Time O(n), stack space O(n).

## Q3.2 Time complexity of:

**a)**
```c
for (int i = 1; i < n; i = i * 2)
    for (int j = 0; j < i; j++)
        sum++;
```
The outer loop runs for i = 1, 2, 4, …, < n (about log n times). The inner loop runs i times, so the total work is 1 + 2 + 4 + … + 2^k < 2n. **Time complexity: O(n).**

**b)**
```c
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);
}
```
T(n) = T(n−1) + T(n−2) + c → the call tree roughly doubles at each level: **O(2ⁿ)** (tight bound Θ(φⁿ), φ ≈ 1.618). Space: O(n) for the recursion stack.

## Q3.3 Pseudocode for finding the largest element in an array.

```
Procedure LARGEST(A, N)
1. [Initialise]   MAX ← A[0]
2. [Scan]         Repeat for I = 1 to N − 1
                      If A[I] > MAX then MAX ← A[I]
3. [Finished]     Write MAX; Return
```
Time O(n), space O(1).

## Q3.4 Compare iteration and recursion with example.

| Iteration | Recursion |
|---|---|
| Repeats using loops (for/while) | Function calls itself |
| Termination by loop condition | Termination by base case |
| No extra stack frames: O(1) space | Uses the call stack: O(depth) space |
| Usually faster | Function-call overhead |
| Infinite loop if condition is wrong | Stack overflow if base case is missing |
| Code can be longer for tree-like problems | Natural for trees, Tower of Hanoi, divide & conquer |

**Example: factorial**
```c
int factIter(int n) { int f = 1; for (int i = 2; i <= n; i++) f *= i; return f; }
int factRec(int n)  { return (n <= 1) ? 1 : n * factRec(n - 1); }
```
