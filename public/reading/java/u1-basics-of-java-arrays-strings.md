### OOP v/s POP Paradigm Comparison

**Procedural Oriented (POP)**

- 1. Program Division:Programs are divided into small, sequential parts called functions.
- 2. Core Focus:Importance is given to the sequence of actions and procedures rather than data.

**3. Structural Flow:Follows a strict Top-Down approach for program execution.**

- 4. Security & Access:Does not have any access specifiers or built-in data hiding.
- 5. Data Movement:Data can move freely from function to function across the system.

**Object Oriented (OOP)**

**1. Program Division:Programs are structured into autonomous, reusable objects.**

- 2. Core Focus:Primary importance is given to data protection and modeling real-world logic.

**3. Structural Flow:Employs a highly modular, scalable Bottom-Up approach.**

- 4. Security & Access:Secures data using specifiers named Public, Private, & Protected.
- 5. Data Movement:Objects securely communicate with each other through member functions.

### OOP v/s POP (Contd.) Paradigm Comparison

**Procedural Oriented (POP)**

**1. Extension: Adding new data and functions is not easy.**

- 2. Data Access: Most functions share global data, which can be accessed freely across the system.

**3. Security: No proper way of hiding data, making it less secure.**

**4. Overloading: Feature overloading is not possible in POP systems.**

**5. Key Examples: C, VB, FORTRAN, Pascal**

**Object Oriented (OOP)**

**1. Extension: Provides an easy way to add new data and functions.**

- 2. Data Access: Data can be public or private to control access, preventing free movement.

**3. Security: Provides strong Data Hiding for enhanced and robust security.**

**4. Overloading: Supports both Function Overloading and Operator Overloading.**

**5. Key Examples: C++, JAVA, VB.NET, C#.NET**

EXECUTION FLOW:The Compiler converts source code into bytecode. Subsequently, the Application Launcher initializes the JRE, loads the required classes, and executes the application's main method.

### Working of JRE

- A step-by-step mechanism of how JRE execution enables write-once, run-anywhere capability.
- 01 / INTEGRATION
- Code & Libraries
- Combines your custom Java code (compiled via JDK) with built-in system libraries to prepare for execution.
- 02 / INSTANTIATION
- JVM Creation
- Creates a local JVM instance (or active copy) that dynamically loads, verifies, and runs the Java application.
- 03 / UNIVERSAL RUN
- Multi-OS Support
- Runs a single compiled copy of your Java code across diverse, platform-specific JVMs built for different OS.

PLATFORM INDEPENDENCE: In this way, the JRE facilitates absolute platform independence for Java applications. You can write your code once and run it anywhere.

### Java Virtual Machine (JVM)

- An engine within the JRE that provides a runtime environment to drive and execute Java applications.
- 01 / RUNTIME
- Execution Engine
- Serves as the core engine providing a virtual environment to load, verify, and run Java code.
- 02 / BYTECODE
- Binary Translation
- Converts intermediate bytecode into hardware-readable binary machine code for execution on host systems.
- 03 / OPTIMIZATION
- JIT Compilation
- Utilizes JIT (Just-In-Time) compilers to translate bytecode into highly optimized low-level machine language.

NOTE ON DEPENDENCY: Although JVM enables platform-independent execution of Java source code, the JVM software itself is platform-dependent and handles memory allocation.

> Bytecode: Computer object code that an interpreter converts into binary machine code so it can be read by a computer’s hardware processors.

### JVM Architecture (Contd.)

- A deep dive into class loading, memory layout, registers, and execution sub-systems.

- Class Loader

- 02 / MEMORY AREA
- Method Area
- JVM Method Area stores class structures like metadata, the constant runtime pool, and the code for methods.
- 03 / SHARED MEMORY
- Heap

All the Objects, their related instance variables, and arrays are stored in the heap. This memory is common and shared across multiple threads.

- 04 / THREAD MEMORY
- JVM Language Stack
- Stores local variables and partial results. A thread has its own JVM stack, creating frames on invocation and deleting them on completion.
- 05 / EXECUTION STATE
- Program Counter (PC) Registers

PC registers store the address of the executing JVM instruction. In Java, every active thread maintains its own independent, separate PC register.

- 06 / EXECUTION
- Execution Engine

Native method stacks hold instructions of native code which depend on native libraries, and are typically written in languages other than Java.

### The main() Method

- The foundational entry point and execution mechanism in Java programming.
- 01 / EXECUTION
- Program Entry
- JVM Entry Point
- Acts as the execution starting point. While not required for compilation, the JVM searches for this exact method to initiate execution.
- 02 / KEY MODIFIERS
- Public & Static
- Access & Lifecycle
- Must be public so the JRE can access it globally. Must be static so the JVM can invoke it without instantiating the class.
- 03 / SIGNATURE
- Void & Args
- Return & Input
- Does not return any value (void) and accepts a String[] array parameter to receive command-line arguments.

### The main() Method rules

- Key behaviors, compiler traits, and structural conventions of Java's entry point.
- 01 / MODIFIERS
- Modifier Order
- Syntax Convention
- The modifiers public and static can be written in either order, but the standard convention is public static.
- 02 / JVM ENTRY
- Strict Rules
- Execution Match
- Any access modifier is compiled, but the JRE requires the exact signature to serve as the active entry-point.
- 03 / PARAMETERS
- Args Naming
- Array Argument
- You can name the array argument anything you want, but most Java developers choose "args" or "argv".
- 04 / EXECUTION
- Runtime Error
- No Compile Errors
- Programs compile cleanly without a main() method, but execution triggers a "Main method not found" runtime error.

### The main() Method Modifiers

- Understanding how public accessibility and static lifecycle control Java's entry point.
- 01 / ACCESS SPECIFIER
- Public Access
- Global JRE Accessibility
- The main() method must have a public access specifier so that the Java Runtime Environment (JRE) can call it from outside of your class.
- Without this public exposure, strict access restrictions will prevent the JVM from executing your program entirely.
- 02 / LIFECYCLE
- Static Modifier
- Instance-Free Invocation
- Must be declared as static so that it can be invoked directly by the JVM without needing to instantiate the class first.
- This provides a clean, predictable starting point for application execution before any objects actually exist in memory.

### The main() Method

- Understanding the void return type and the fixed method identifier.
- 01 / RETURN TYPE
- Void Return Type
- No Return Value Requirement
- The main() method in Java is declared with a return type of void to indicate that it does not return any value.
- Its purpose is simply to serve as the entry point for the Java program, invoked by the JVM to start execution.
- 02 / IDENTIFIER
- Main Method Name
- Fixed Starting Signature
- It's just the name of the method. This name is fixed because it is called by the JVM as the entry point for an application.
- Note that while the name is strictly required by the launcher, main is not a keyword in Java.

### Type Conversion & Type Casting

- 06 / Language Fundamentals

- 01 / THE CHALLENGE

- 02 / PRACTICAL CASE

- 03 / JAVA SOLUTION

Since Java is strongly typed, type conversion is crucial. The programmer or compiler can easily manage this using type casting and type conversion concepts.

### 07 / Language Fundamentals Type Conversion

- 01 / AUTOMATIC PROCESS

**Implicit Action**

Type conversion is a process in which the data type is automatically converted into another data type. The compiler does this automatic conversion at compile time.

- 02 / MANDATORY RULE

**Size Requirement**

For type conversion to take place, the destination data type must be larger than the source type, ensuring there is enough capacity to hold the value.

- 03 / SAFE WIDENING

**No Data Loss**

Also called Widening Type Conversion, Implicit Conversion, or Casting Down. As smaller types are converted to larger ones, there is absolutely no chance of data loss.

- We can create a wrapper object using the wrapper class and its constructor by passing the value to it.

**Syntax:**

**ClassName object = new ClassName(argument);**

**Example:**

**Integer number = new Integer(58);**

**STATUS & WARNINGS**

**Usage Status**

- DEPRECATED
- However, the way of creating an instance of wrapper classes using constructor is deprecated as of the latest version of JDK.
- This is because each time new memory is allocated in the heap when we create an object with the help of the constructor.
- Also, the constructor Character(char) has been deprecated since JDK version 9.

### Autoboxing

- 09 / Language Fundamentals

**CONCEPT DEFINITION**

Autoboxing is when the Java compiler performs the automatic conversion of the primitive data types to the object of their corresponding wrapper classes.

- For example, converting an int to Integer, a double to Double, etc.

**EXPLICIT CONVERSION**

**To explicitly convert primitive to object we use the valueOf() method.**

**COMPILER BEHAVIOR**

**The Java compiler applies autoboxing when a primitive value is:**

- Passed as a parameter to a method that expects an object of the corresponding wrapper class.
- Assigned to a variable of the corresponding wrapper class.

### Auto-Unboxing

- 09 / Language Fundamentals

**What is Unboxing?**

- Unboxing is automatically converting an object of a wrapper type (Integer, for example) to its corresponding primitive (int) value.

**Explicit Conversion**

- To explicitly convert object to corresponding primitive type we use xxxValue() method.

**Automatic Unboxing**

- The Java compiler applies unboxing when an object of a wrapper class is:
- Passed as a parameter to a method that expects a value of the corresponding primitive type.
- Assigned to a variable of the corresponding primitive type.

### toString() Method

- 09 / Language Fundamentals

**Core Purpose**

**String Representation**

- The toString() method returns the String representation of the object.

**Compiler Behavior**

**Automatic Invocation**

- If you print any object, Java compiler internally invokes the toString() method on the object.
- So overriding the toString() method, returns the desired output, it can be the state of an object etc. depending on your implementation.
